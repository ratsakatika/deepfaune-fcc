Camera-trap classification: user guide

This tool reviews the camera-trap photographs on the hard drive and records the species in each image. It then produces summary tables and an interactive dashboard and result filter page. The first part of this guide is all you need for everyday use; the later sections explain the settings, the result files and what to do if something goes wrong.

1. Quick guide: running the tool

  1. Connect the "My Book" hard drive to the computer.
  2. Open the Run DeepFaune icon on the desktop (double-click it).
    The first time only: right-click the icon and choose Allow Launching, then open it.
  3. If a newer version is available, the tool offers to update itself first; answering y is safe and takes a few seconds. After updating it closes so the new version loads cleanly: just open it again.
  4. The tool finds the hard drive and reports how much of the archive is already done. Press Enter to accept the drive it found.
  5. It then asks you to confirm a few settings. If you are continuing an existing run it says "Reusing from that run" and suggests exactly the settings that run used; press Enter to accept each one, or type a new value and press Enter. Confirm with Y at the end.
  6. Processing begins. A live display shows how many images are done, the percentage complete, and the estimated finish time.

2. What the settings mean

Press Enter to accept the suggested values; they are sensible for this survey, and when you are continuing a run they are that run's own settings, so the whole archive stays consistent. If you do want to change one, here is what each means.

  • Detector - the first stage, which finds the animal, human or vehicle in each photo. A separate model then names the species, and that part is the same whichever detector you choose. From fastest to most thorough:
    • DF - DeepFaune's own detector, trained on European camera-trap images. The lightest and fastest.
    • MDS - MegaDetector "sorrel", the widely used general-purpose detector. Similar speed to DF but trained differently, so it finds some things DF misses.
    • DFbsMDS - runs DF first and tries MDS only on photos where DF found nothing. A cheap way to recover a few extra animals.
    • DFMDS - runs both detectors on every photo and merges the results. The most thorough of the standard options, but the slowest.
    • MDR - MegaDetector "redwood" at higher resolution. Meant for a computer with a graphics card; avoid it on this machine.
  • Birds - when on, birds are also sorted into groups such as corvid, raptor or passerine, instead of just "bird".
  • Confidence threshold - how sure the tool must be before it names a species. Higher (for example 0.8) means it only commits when very confident: fewer wrong names, but more animals left labelled "undefined". Lower names more photos, but more of those names are wrong. Whatever you choose here, the raw scores are all recorded, so the threshold can be changed later in the dashboard page without reprocessing anything.
  • Sequence gap (maxlag) - photos taken within this many seconds of the previous photo at the same camera are chained into one sighting (a "sequence" or detection event), so a burst of frames is counted once. Note the chain can be much longer than the gap itself: an animal that lingers keeps re-triggering the camera, and each photo within the gap of the previous one extends the same event.
  • Batch size - how many image crops are classified at once. Affects speed and memory only, never the results.
  • Processor cores - how much of the computer to use. More is faster but uses more memory and runs hotter.
  • Update interval - how often the master results file refreshes during a run. Affects how often you see progress, not the results.
There is no species-exclusion setting. Excluding species that cannot occur here (ibex, reindeer and so on) is done afterwards in the dashboard and result filter page, where it is reversible and gives an identical result, because the raw score for every species is recorded regardless.

3. While it is processing

  • A large archive can take several days. This is expected.
  • You may close the window or disconnect from the computer (if connected remotely); processing continues on the computer itself. Closing the live display with Ctrl+C also only closes the display, never the run.
  • Open the Run DeepFaune icon again at any time to view progress.
  • Keep the hard drive connected while it runs.
  • Progress is saved folder by folder, so nothing is ever lost by a stop: the tool always resumes from where it left off and never repeats finished work.

4. Adding new photographs later

In normal use you will not reprocess the whole archive. When you copy new camera-trap photographs onto the hard drive, run the tool again. It processes only the new folders and refreshes the result files. This is the main day-to-day use of the tool.

5. The result files

These are saved to the desktop and refreshed at the end of a run (the master also refreshes during the run):

  • dashboard_and_filter.html - the interactive dashboard and result filter. Open it in a web browser; see the next section.
  • deepfaune_wildlife.csv - the animal detections only. Opens in Excel.
  • deepfaune_summary.csv - totals per species and per camera. Opens in Excel.
  • deepfaune_master.csv - one row for every image, with the full raw model outputs. This file is very large, so open it in R (or load it into the dashboard page) rather than Excel.

Working files stay in ~/df_out: one CSV per photo folder (the source of truth, and what makes resuming possible), the merged master.csv, the run's settings and status files, and a detailed log.

6. The dashboard and result filter page

Open dashboard_and_filter.html in a web browser and choose the master CSV (or drag it in). Everything is computed on your own computer; nothing is uploaded. The page shows the survey statistics, a camera map (the camera positions are built in), a day-and-night activity ring, seasonal charts, species and busiest-camera charts, and a table of every detection event.

Its key idea: because the raw score for every species is recorded for every image, the page re-derives the predictions under whatever rules you set, without reprocessing anything. You can:

  • set a different confidence threshold, overall or per species;
  • untick species that cannot occur in the survey area (there is a one-click Romania preset), so their detections fall to the next-best species;
  • require a minimum sequence length in seconds;
  • include or exclude empty, human and vehicle events, and choose between the official survey and all images;
  • click a table row to preview that event's photographs (when the image files are reachable from where the page is opened);
  • save any figure as an image, and download the filtered results as a CSV per event or per image.

To use it from a phone or tablet on the same network: on the computer run cd ~/Desktop && python3 -m http.server 8000, then open http://<computer-ip>:8000/dashboard_and_filter.html in the phone's browser. Served this way it loads the master file automatically.

7. Understanding the result columns

Each row of the master (and wildlife) file is one image:

ColumnMeaning
filename, date, seqnum The image, its date from the camera, and the sequence (detection event) it was grouped into.
prediction_seq, top1_seq, score_seq, above_threshold The sequence-level verdict. Below the threshold prediction_seq reads "undefined", but top1_seq keeps the best-scoring species and score_seq its score, so no information is lost.
prediction_image, top1_image, score_image The same, per single image (no sequence averaging).
animal_count, human_count How many animal and human boxes the detector found.
det_conf_animal / _human / _vehicle The detector's best box confidence per category (0 = nothing found).
score_<species> (one column per species) The classifier's raw score for every species, recorded whatever the threshold. Blank when no animal was found (there was nothing to classify). These columns are what make the retrospective filtering possible.
birdscore_<group> (when birds is on) The bird sub-classifier's scores; only meaningful when the animal is a bird.
sequence_id A globally unique key for the detection event, formed from a short code for the folder plus the sequence number. seqnum alone is not unique (it restarts at 1 in every folder), so always count events by sequence_id. The id is stable: the same event keeps the same id however the results are rebuilt.

8. If processing stops

  • Drive disconnected or computer restarted: reconnect the drive and open the Run DeepFaune icon again. The tool resumes from where it stopped with the same settings, and never repeats finished work.
  • Crashes: if the auto-resume service is installed, a run that dies of a crash or memory exhaustion restarts itself within two minutes, with its own settings. A run you stopped on purpose stays stopped, and nothing starts by itself after a reboot.
  • Finding out what happened: in a terminal, dfrun --diagnose prints the run's settings, the last recorded system readings and a one-line verdict (memory exhaustion, full disk, drive disconnect, reboot, or software fault) without touching the run.

9. Useful commands

Everything below is optional; the desktop icon covers normal use. In a terminal:

CommandWhat it does
dfrunStart or resume a run, or reattach to the live display of a running one.
dfrun --stopStop the run cleanly. Nothing will restart it until you relaunch.
dfrun --diagnosePrint settings, progress and a verdict on why a run stopped, without touching anything.
dfrun --outputsRebuild the master and desktop files from the finished work, without reprocessing anything.
dfrun --install-serviceInstall the auto-resume service (see above). --uninstall-service removes it.
